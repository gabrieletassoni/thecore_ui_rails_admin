# `change_password`'s error rendering is hand-rolled, not RailsAdmin's field-generation machinery

`change_password` is a custom member action with its own `form_for(@object, ...)` view, not one generated from a `RailsAdmin::Config::Fields` field list the way `edit`/`new` are — there is no field config for it to derive automatic field-level error markup from. When we needed the failed-validation re-render (flash box + red-bordered fields) to look like RailsAdmin's standard `edit`/`new` error state, we considered reusing RailsAdmin's internal field-rendering partials/helpers, but rejected that: those helpers are coupled to the field-config-driven form generator and are liable to change across RailsAdmin versions in ways not aimed at custom actions. Instead we replicate the same visual pattern (`flash.now[:error]` + an error CSS class on the two password fields) by hand in `change_password.html.erb`. Do not "fix" this by wiring the action into the field-generation system — there's nothing for it to hang off.
